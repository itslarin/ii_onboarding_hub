# Настройка OpenSpec в проекте

Установка OpenSpec описана в `01-setup/windows/03-openspec.md`. Здесь —
проектная настройка: то, что превращает CLI в рабочий инструмент команды.

## Порядок действий (важно соблюдать)

1. **[Инициализация `openspec init`](01-init.md)** — создаёт папку `openspec/`,
   `config.yaml` и workflow-файлы (skills). Выбираем OpenCode как AI-инструмент.
2. **[Заполнение `config.yaml`](02-config.md)** — вносим контекст проекта
   (Kotlin/Spring Boot/Maven) и правила для артефактов.
3. **[Плагин `opencode-plugin-openspec`](03-plugin.md)** (опционально) —
   добавляет в OpenCode отдельного агента `openspec-plan` для планирования
   без риска случайно изменить код.

## Почему именно такой порядок

- `openspec init` создаёт `config.yaml`. Если отредактировать конфиг до
  инициализации, `init` может его перезаписать или создать структуру заново.
- Плагин имеет смысл подключать, когда OpenSpec уже инициализирован:
  он автоматически определяет OpenSpec-проект и активирует агента
  `openspec-plan` только в таких workspace.
